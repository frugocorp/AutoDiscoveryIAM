# SimpleCode

Ejemplos de código **copiables**, no proyectos que compilan como parte de esta solución — a diferencia de `samples/AutoDiscoveryIAM.SampleHost/` (que sí es un proyecto real y ejecutable), esto es solo material de referencia para copiar y pegar en tu propio proyecto.

- **[`Data/ApplicationDbContext.cs`](Data/ApplicationDbContext.cs)** — el `DbContext` propio de la app (transversal, hermano de `Features/`, nunca anidado dentro de una sola feature). Hereda `AutoDiscoveryIAMDbContext` de la librería (contexto único: un solo modelo, una sola migración) en vez de declarar el suyo aparte -- ver [Elige tu propio DbContext: uno o dos](../../README.md#elige-tu-propio-dbcontext-uno-o-dos) en el README principal para esta opción y su alternativa (dos `DbContext` separados).
- **[`Features/FeaturesDependencyInjection.cs`](Features/FeaturesDependencyInjection.cs) y [`Features/FeaturesEndpointMapping.cs`](Features/FeaturesEndpointMapping.cs)** — concentradores, hermanos de `Features/UserProfiles/`: el único punto donde `Program.cs` necesita conectarse (`AddFeaturesDI()`/`MapAllFeatureEndpoints()`), sin importar cuántas features tengas.
- **[`Features/UserProfiles/`](Features/UserProfiles/README.md)** — ejemplo completo de una feature propia (`CreateUserProfile`/`GetUserProfiles`) siguiendo la misma arquitectura Vertical Slice de la librería, con todas las piezas incluidas por default (Validator, Catalogs, OpenAPI, Logging, Services de consulta reutilizables) — más fácil borrar lo que no quieras que reconstruirlo desde un ejemplo simplificado. `UserProfile` tiene además un FK real hacia el `User` de la librería, la demostración en código de cómo agregar datos por usuario sin tocar `User`. Ver [Ejemplo: arquitectura Vertical Slice en tu propia app](../../README.md#ejemplo-arquitectura-vertical-slice-en-tu-propia-app) en el README principal para la explicación paso a paso.
